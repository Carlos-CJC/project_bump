# Bump｜MQTT v1 协议兼容实验

这是一份独立的桌面副本，Windows x64 与 macOS / Linux 均可运行（Windows 双击 `Start-Bump.cmd`，macOS 在 `group9` 目录执行 `./run.sh demo`）。原版的模拟发现、联系邀请和同意仍保留。新增的是另一条**软件协议实验**轨道：用两枚虚构挂件发上传材料约定的 MQTT 报文，检查本机数据库能否收到、去重和匹配。没有给开发板刷固件，也没有测真实 BLE 距离、RSSI、NFC 或在线状态。

## 先试一次

1. 在**这个文件夹**双击 `Start-Bump.cmd`。离线运行环境随汇总包提供。用记事本打开启动窗口给出的 `.runtime\credentials.txt`，在对应账号行的密码首字符前点击，按 **Shift+End**、**Ctrl+C**，再粘贴到网页。口令末尾若有短横线或下划线也要复制。已有的演示账号和记录可继续使用；全新解压首次启动会生成独立账号。
2. 登录 **alice**，在已登录工作台展开 **MQTT v1 协议实验**，点击 **运行双端上报**。它只接受这个固定动作，不从网页接收任意主题、设备、事件或文件。
3. 看到协议结果后检查相遇卡片：Alice 看到 B00002，Bob 登录后从另一侧看到 A00001；Charlie 没有参与这项实验。实验软件客户端在成功上报后会主动发 offline 再断开；页面显示模拟设备离线并不等于本次没有收到记录。仅显示虚构化名和本账号的观察，双方互遇**不等于同意公开资料**。
4. 同一台电脑可继续使用原来的“模拟发现”和联系邀请；它们有单独的事件与同意记录，不会被本实验填充。若实验显示未确认，先刷新记录；部分写入不等于完全失败，不要自动连点重试。
5. 在服务窗口按 Ctrl+C 停止。若旧项目已在运行，首次启动新副本会选择可用回环端口；使用**新窗口显示的 URL**。两版本的网页会话 Cookie 名不同。

## 一条消息怎样变成卡片

| 环节 | 本兼容副本的行为 |
|---|---|
| 接收 | `bump/v1/device/{device_id}/encounters` 传 1–8 个事件；`.../status` 表示软件设备状态。MQTT 3.1.1、QoS 1、TLS、设备凭据、按方向限制主题权限。端口仅绑定本机回环。 |
| 校验 | 限原始 UTF‑8 报文 ≤2,048 字节，校验 schema、设备/boot/事件/批次标识、时间与整数类型；不是“8 条就一定装得下”。普通 status 和 retained 重放分开处理；encounters 不作为 retained 数据处理。 |
| 存储 | 新轨道使用 `bump-v1.sqlite3`，以 event_id 去重。同键冲突或无效批次不当作新成功；重复上报不会使隐藏记录复活。数据库和网页不共享原版联系资料。 |
| 匹配 | 只有窗口内、无歧义的短号映射可回填；对向观察在约定的 900 秒窗口内才能标为互遇。8 小时是展示聚合，不是原始事件去重，也不是同意联系。 |
| 结果 | 网页的“已持久化”表示服务器确认本次两条软件观察已进 SQLite。MQTT PUBACK 只是传输回执；这个 v1 原型不向设备发送“已入库”应用 ACK。原轨道的应用 ACK 语义没有改变。 |

## 兼容边界

- 上传的 `docs.zip` 只含 `FEATURES.md`、`INTERFACES.md`、`FIRMWARE_MQTT_PLAN.md`，没有源代码包、二进制或可刷入的固件。来源和 SHA‑256 见 `docs/upstream-v1/SOURCE.md`。
- 实做的是**本机协议子集**，不是整套生产服务器。未开放公网/局域网、未接入真实挂件、真实串口或外部 MQTT 代理，不把硬件 MAC 或原始包暴露给网页。
- `GET /api/v1/health` 提供匿名的通用健康信息。实验网页沿用本地登录 Cookie 与逐会话 CSRF，**不提供附件草案的完整 Bearer API、设备绑定/解绑、设备配置下发或资料服务**。
- 为维持原有开发 broker 的隔离，兼容服务仍只接受 clean-session 连接，不使用断线遗嘱；持久订阅跨断线补发、长期队列和实体端 NTP/节电表现需另行接入验证。软件显式状态不证明实体硬件在线。
- 短号冲突宁可显示“未解析”，不会猜设备身份。新卡片从不显示联系人资料；若要演示双方同意，请使用原版的独立社交链路。
- 不分发 `.runtime\`（含随机密码、证书和演示记录）；无需关闭防火墙、绕过 TLS 验证或改网络设置。
