# Bump 0.1.0 实施调整

2026-10-23。核心目标仍为 IMU 主动开窗、双机相遇、可靠上传和双方同意分享资料。
以下是针对“暂时没有实物和传感器”的实施调整。

| 调整 | 原因 | 当前边界 |
|---|---|---|
| 先模拟器、服务器、网页、异常权限，再固件核心 | 四人可以立即开发并核对同一份协议，不被到货时间阻塞 | 不推断任何传感器或无线性能 |
| 本机开发版内置 aMQTT，替代单独安装 Mosquitto | 一次 Python 环境安装即可复现；降低组员启动门槛 | 保留标准 MQTT 3.1.1；后续换 Mosquitto 需重测认证、ACL、TLS 与重连 |
| 只监听 localhost，每台电脑独立生成密码和 CA | 演示资料隔离，避免把共享密码和私钥打进源码包 | 局域网/真设备接入仍需地址、证书、设备信任根和网络验证 |
| 固定 schema、完整事件键、来源和时间质量 | 防止重传增行、ACK 清错记录、不同设备 uptime 被误匹配 | source=simulated 与 hardware 不互配 |
| 60 秒窗口在模拟场景里快进 | 快速检查状态边界，便于回归 | 不能宣称已测量实际 60 秒窗口或感应时延 |
| 时间线移除采用 soft-hide，撤销联系单独处理 | 删除后重传不使记录复活；撤销后资料重新隐藏 | 不声称抹除数据库全部证据或对方已保存副本 |
| 默认固件串口模拟，真实 IMU API 单独编译 | 在没有实物时检验共享 C++ 核心和板卡接口，并保留真实可追溯边界 | BLE/Wi-Fi/MQTT、boot_id/校时和采样效果仍要完成接入与实测 |
| 修复切换账号时的异步响应竞争 | 防止旧账号请求迟到后覆盖新账号页面 | Node 回归覆盖该竞争；仍需保留服务端对象权限 |
| MQTT 新连接先认证再处理旧会话，仅接受 clean_session=True | 防止失败的重复连接影响已经认证的会话；保持本地设备身份与权限一致 | 针对固定 aMQTT 版本提供本地子类；升级依赖后必须复测 |
| 撤销和移除使用页面内确认框 | 避免嵌入浏览器的原生 JavaScript 确认框兼容问题 | 交互的实际核验范围记录在 browser/verification.json |

完整四人交接手册 v1.1 同步更新了已完成工作、启动方法、证据和到货后的检查顺序。
原 v1.0 保留作为历史记录，四人应统一阅读 v1.1。
