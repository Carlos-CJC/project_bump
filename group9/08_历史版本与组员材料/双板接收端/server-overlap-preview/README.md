# Bump 双板共同开窗匹配预览

此目录独立于原接收端和先前的匹配预览。此版沿用 0.5.3 以来的 BLE 开窗字段、MQTT ACK、账号、红外邀请和网页接口，按双方实际开窗窗口的交集判断。开发与回归只使用合成报文和临时 SQLite 数据库。

## 如何匹配

- 两端须解析为各自观察到的开机短号，传输来源一致，且没有第二条可能的反向观察。过往轮次的记录单独绘制，较新的卡片不会继承历史匹配状态。
- 0.5.3 上报每个观察所属的 60 秒发现窗。各方向真实采样跨度至少 3 秒，共同发现时段须能容纳任一方向的完整跨度，且推算后的采样起止同时位于共同发现时段内。网页随后标为「双方记录已匹配」。开窗起点没有固定差值上限，两方向的采样区间可以互相错开。推算端点前后容许 2 秒，包括设备时长按整秒上报以及本机记录时间的误差。这个容差不延长可用于容纳采样的交集时长。
- 时间窗口相交但无法容纳实际采样、估算采样端点超出容差，或有多条候选时，显示「双方观察 · 轮次待核对」。旧包没有开窗数据，72 秒内精确互指的观察也只作为待核对候选。没有反向候选保留为「单方记录」。仅已匹配的 BLE 卡片允许运用手动邀请，红外邀请仍由独立红外配对触发。
- 事件以最后采样时间作为 UTC 锚点。固件用发送时的设备运行时间与原采样时间的差值估算 UTC，支持同一次开机内的计数回卷。窗口边界沿用这个锚点，再减去最后采样到开窗的间隔。设备有 NTP 记录时沿用事件的 NTP 时间。网络收包时间另存，重发相同事件只返回 duplicate，保留首次入库的时间和证据。

## 启用

在空闲时停止原接收端并备份当前运行数据库。沿用已存在的运行目录、网页端口、MQTT 端口和账号，改为启动此目录的入口。无需再次执行 init。

~~~powershell
$python = '.\Bump_EIE568_MQTT_v1_兼容演示\.local-tools\python312-ac9f8f76cdc4\python.exe'
$receiver = '.\2026-11-18_双板联调\server-overlap-preview\live_server.py'
$runtime = '.\2026-11-18_双板联调\private\live'
$env:PYTHONDONTWRITEBYTECODE = '1'
& $python -X utf8 $receiver serve --runtime $runtime --mqtt-host 192.168.137.1
~~~

IP 使用本次临时网络的接收地址。停止挂件传输后，可用同一命令把 MQTT 监听地址改为 127.0.0.1，继续从 [本机网页](http://127.0.0.1:8875) 查看已保存数据。启用 0.5.3 固件前先换接收端，旧接收端还不认识新增字段。

首次启动在原 observations 表末尾添加两个可空时间列，原账号、红外记录、邀请和偶遇 ID 保留。原偶遇没有窗口边界，按旧包规则投影。已启用先前匹配预览的原数据库无需额外迁移。此目录的 inspect 命令会输出两列估算窗口 UTC 时间，便于和板端同轮日志交叉核对。

## 回归

~~~powershell
& $python -X utf8 .\2026-11-18_双板联调\server-overlap-preview\matching_test.py --demonstrate-baseline
& $python -X utf8 .\2026-11-18_双板联调\server-overlap-preview\matching_test.py --demonstrate-skew-limit
& $python -X utf8 .\2026-11-18_双板联调\server-overlap-preview\matching_test.py
& $python -X utf8 .\2026-11-18_双板联调\server-overlap-preview\smoke_test.py
~~~

基线小例重现了同两板相差 180 秒、跨启动短号及新卡借用历史互遇三个误判。旧 12 秒规则的复现使用 0.5.0 手摇开窗相差 12.247 秒这一实测数值，与合成 BLE 采样窗口组合。定向回归保留该例、真实样本位于交集的 20 秒错位、样本不在交集的 20 秒错位、交集太短、边界小偏差、相邻窗、候选歧义、旧包及 SQLite 增量迁移。离线首传跨计数回卷并晚一小时入库，仍还原原时刻，之后重发去重。真实双板互遇需另用同轮设备记录与网页结果验收。
