# 两块实板的原始固件与恢复操作

本目录记录 2026-11-18 用户授权的两块 Nano RP2040 Connect。A 的原始红外机器码是 A30F，B 的是 C371。两块板的完整 RP2040 外部闪存镜像保存在本机 private 中。每个镜像覆盖 0x10000000 起的 16 MiB，包含程序和其余可寻址闪存。NINA 模块有独立存储，本次操作只涉及 RP2040。

## 恢复原始固件

恢复会覆盖所选板 RP2040 整片闪存。执行前应确认要恢复的板，并将另一块实板从 USB 暂时拔下。读取 private/original_A.json 或 private/original_B.json，以 USB 序列号、原始 Chip UID、红外机器码及物理端口逐项确认。用 PowerShell 的 Get-FileHash -Algorithm SHA256 核对同一块板的 original_A.bin 或 original_B.bin，文件长度应为 16777216 字节。

通过该板的 Arduino USB 串口 1200 波特率触碰进入 BOOTSEL；必要时按板卡说明用 REC 与 GND 在复位时进入。确认目标串口消失、目标物理端口出现唯一的 RPI-RP2，执行 picotool info -a 检查设备和 16384K 容量。工具位置见 original_backup.py。以下为 A 的恢复命令，B 对应使用 original_B.bin。在本机 private 目录下运行。

    picotool load -v original_A.bin -o 0x10000000
    picotool verify original_A.bin -o 0x10000000
    picotool reboot -a

等待 Arduino 串口恢复，在 115200 波特率下打开串口，读取 IR Near-Field Pairing、Chip UID 和机器码，并发送 s 查看 IDLE。先后逐块核验。

本轮使用整片实际读取、picotool 与实物的逐字节比较、SHA-256、原程序回启检验可恢复性。覆盖写回原镜像属于后续需要恢复时的操作。private 内可能含设备配置，只应在本机保留。
