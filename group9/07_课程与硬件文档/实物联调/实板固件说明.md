## 0.5.7-dual 的板载灯与暂停回归

提案的即时相遇提示使用 RP2040 的独立板载灯。真实 BLE 对端达到信号及停留门槛后点亮 D13，开窗结束或用户取消时熄灭。正常结束后，板载 RGB 切换至黄色两秒，再回到当时的红外状态。白键先暂停发现，再处理红外解除；红外空闲时再次按白键恢复。按键取消的窗口丢弃未提交的观察。

两板安装、闪存回读及单轮实物射频验证已完成。A 与 B 分别在首次样本后 3.491 和 3.412 秒将 D13 读回为高，闭窗都读回为低。RGB 在请求黄色和恢复白色时均返回 000，尚缺可辨别颜色的实物观察。本版暂停与恢复由串口调用同一白键处理函数验证。0.5.6 的 20 轮观察保留原版本归属。

## 固件版本

- 0.5.6-dual 对照版把 TCP、MQTT CONNECT/SUBACK/PUBACK 和应用回执的等待设为 12 秒。串口 sync_stage 记录各阶段耗时和结果，wifi_link 在断开 Wi-Fi 前报告实读板端地址和 RSSI。提交测试仍用原 65 秒上层验收窗口。
- 0.5.5-dual 候选把 BLE 结束路径改为主控清理后直接拉低 NINA 复位线。原生驱动按同一顺序重新启动 NINA，供下一段 BLE、LED 或 Wi-Fi 使用。NINA 的收包缓冲随复位清除，RP2040 的样本、应用队列和网络配置在正常切换中保留。RP2040 看门狗复位仍会清除它自己的 RAM。
- 0.5.4-dual 用项目内 ArduinoBLE 副本限制 HCI 轮询，保留相同主动扫描参数和数据格式。复位记录可区分 SPI 查询可用量和单字节接收。[最小对照探针与限制](无线驱动与复位说明.md)
- 0.5.3-dual 在每条可上报的 BLE 观察中保存本次发现窗的起止时间。离线补发沿用原窗口和观察时间，批次发送时间重新取值。Bump 名称、A5B0 与厂商数据均放在不可连接主广播中，扫描响应留空。
- 0.5.2-dual 在 60 秒窗口内采用两个互补收发阶段，第一段持续约 28 秒，第二段到窗口结束。重复扫描报告仍启用，保留原有偶遇门槛。扫描循环每 5 ms 最多调用一次库入口。
- 0.5.2 的发现阶段由 8 秒硬件看门狗守护。复位后 status 的 last_watchdog_stage 和 pre_reset_ram_queued 提供停止位置和复位前的待确认队列数。复位会清除 RAM 队列、Wi-Fi 和 MQTT 配置，该轮需记为中断。空闲时读取一次实际 NINA 版本，出现在 nina_version。复位触发来自版本读取时，本次启动跳过该查询。
- 0.5.2 通过 RP2040 环形振荡器为每次开机分别生成短 ID 和启动号。硬件熵读不到时，固件记录错误并暂停发现和事件上报。双板分别经初次安装启动和三次额外复位，共八组启动号和短 ID 均不同。两板均实读 NINA 3.0.2。[实板复位记录](../../06_测试结果/早期双板与断网/设备/startup_regression_0.5.2.json)
- 0.5.1-dual 在 ArduinoBLE 扫描时启用重复报告。仍按 400 ms 间隔采样，沿用 60 秒、−70 dBm、至少 2 样本与跨度 3 秒。稳定文件与校验清单在 releases/0.5.1-dual。
- 0.5.0-dual 的 UF2、源码和核验清单存放在 releases/0.5.0-dual。

## 串口与按键

串口用 115200，命令以换行结束。

| 命令或输入 | 行为 |
|---|---|
| status | 显示 device_id、boot_id、实际广播 self_short_id、红外机器码、动作、队列和网络配置状态 |
| i / q | 打开或关闭每秒状态与 IMU 采样输出 |
| discover | 诊断开启 60 秒广播与扫描，来源记为 serial_diagnostic |
| SET ble_role a / SET ble_role b | 下一窗先扫描或先广播。A30F 默认先扫描，C371 默认先广播 |
| 蓝键 / b | 开始红外搜索。若正在 BLE 发现则取消该窗 |
| 白键 / w | 结束当前红外会话。红外空闲时切换 BLE 发现暂停 |
| pause | 仅切换 BLE 发现暂停 |
| SET ssid、SET wifi_password、SET broker_host、SET broker_port、SET mqtt_password | 按「SET 键 值」逐行配置。broker_host 只接受私有 IPv4，默认端口 18883。MQTT 用户名使用状态所示 device_id |
| sync | 在发现窗口及红外握手结束后安排直连发送。完整配置也会触发首次 presence |
| dump | 逐条输出 presence 和当前待发事件，含 topic 与完整 JSON |
| SET transport serial_bridge | 切换为 USB 导出后中转。中转入库后用 ACK 加空格和原样 JSON；只处理已由 dump 导出的队首 |
| SET transport wifi_mqtt | 恢复板端本地 MQTT TCP 发送 |
| r / t | 重启 / 进入 USB 启动盘。重启、掉电或重刷会清除 RAM 队列、网络参数和本次启动短 ID |

直接 MQTT 与 USB 中转应在日志中区分。每次网络会话先发在线 presence，随后发待确认项并等待本设备应用回执，最后发离线状态。broker PUBACK 和服务确认分开记录，回执必须匹配事件编号且 status 为 stored 或 duplicate。断网时保留队列并在设备继续供电时每 15 秒重试。传输使用局域网认证 TCP。两个设备应分别设置各自的 MQTT 密码。

红外协议、引脚、物理按键和四态灯色复用组员附件。NINA 同时参与 RGB 和无线通信，BLE 或 Wi-Fi 占用期间关闭板载 RGB，释放无线资源后按红外状态恢复 LED。配对成功进入绿灯，握手补发结束后才允许网络上传。

## 重建

使用此前单板安装的 Arduino CLI 与 Arduino Mbed Nano 4.6.0，目标 arduino:mbed_nano:nanorp2040connect。现有库版本为 ArduinoBLE 2.1.0、Arduino_SpiNINA 0.0.2、WiFiNINA 2.1.1、ArduinoMqttClient 0.1.8、Arduino_LSM6DSOX 1.1.2。IRremote 4.7.1 来自 Arduino 库索引并核对 SHA-256，保存在 vendor/libraries。

在本目录用 PowerShell 执行：

~~~powershell
$tool = 'E:\港理课程\网站维护\任务工作记录\2026-10-23_eie568_lab1\toolchain'
$env:ARDUINO_BUILD_CACHE_PATH = Join-Path (Get-Location) 'cache'
& "$tool\bin\arduino-cli.exe" compile --config-file "$tool\arduino-cli.yaml" --fqbn arduino:mbed_nano:nanorp2040connect --libraries "$PWD\vendor\libraries" --library "$PWD\nina_probe\ArduinoBLE-reset" --build-path "$PWD\build" "$PWD\BumpDualBadge"
~~~

上面命令对应 0.5.5 和 0.5.6。重建 0.5.4 时选该版归档源码及 ArduinoBLE-limited。重建 0.5.3 或更早版本时选相应的归档源码并省略 --library 参数。生成 build/BumpDualBadge.ino.uf2，已验证的版本、UF2 与校验清单各自归档在 releases。组员原版的独立构建保存在 baseline-build，原板闪存备份由实板测试步骤单独核验。
